Let’s watch it run

Demo order

  1. Commit a visible change → pipeline → canary → new version live
  2. FAIL_TESTS → a failing test blocks the release
  3. SIMULATE_CANARY_FAILURE → automatic rollback
  4. Grafana: stable vs canary containers

Lessons learned

  • A test stage catches config errors, not only code bugs
  • Read the server-side log first
  • One digest from test to prod: no surprises
  • Automate rollback before you need it

Future work

  • Data on AWS: RDS + S3
  • More canary stages, metric-based gates
  • GitHub webhook instead of polling
  • HTTPS
  • Fully separate test database
