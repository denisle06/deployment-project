Pipeline as code · Jenkinsfile

Four stages from commit to production

Trigger: polls GitHub every 2 min · image tag = short Git SHA · one digest for test and prod

1 · jenkins EC2

Build

  • PHP syntax lint
  • docker build (PHP 8.3 + Apache)
  • Version baked in: /healthz.php + X-App-Version header

2 · Docker Hub

Push

  • Push image tagged with the SHA
  • Record the immutable digest
  • Test and prod run the byte-identical image

3 · test EC2 agent

Test

  • Container from that digest, test settings
  • 11 smoke + integration tests
  • JUnit report; any failure blocks the release

4 · prod over SSH

Deploy (canary)

  • Prod settings streamed, owner-only file
  • Canary next to stable, 10% → 100%
  • Gates fail → automatic rollback

(~2 min) The whole pipeline is a Jenkinsfile in the repo. Jenkins polls GitHub every 2 minutes, so a merge to main starts it automatically: that is L4. Build: PHP lint, then docker build on PHP 8.3 + Apache; the image is tagged with the short commit SHA and the version is visible at /healthz.php and in an X-App-Version header. Push: to Docker Hub, and we record the digest, so test and prod run exactly the same bytes. Test: on the separate test EC2 agent, 11 automated tests: health and DB, version, auth redirects, login and register pages, song catalogue JSON, static assets, secrets not exposed, a register-plus-login flow, and a recording upload that must score 60 to 100. Results show as a JUnit report; any failure stops the release. Deploy: next slide.
